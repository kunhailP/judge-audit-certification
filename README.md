# Certifying retrieval policies with non-neutral AI judges — code, results and pre-registration record

Research artifact for the manuscript *Certifying Retrieval Policies with Non-Neutral AI Judges: What a Judge Saves, and How a
Pilot Predicts It* (under review at TMLR). Every number in the paper is regenerated from the row-level result files under
`05_results/` by the scripts under `04_code/`; the lock documents under `03_data/` and the log in `05_results/heldout/LOCK_NOTE.md`
are the pre-registration record (see the section below for what the commit history does and does not show).

## Layout
| Path | Content |
|---|---|
| `01_design/` | Development log (design, every negative result, retraction and post-hoc change) and the menu-allocation exploration note |
| `03_data/` | Pre-registration locks v0.4–v0.7, the ε = 0.03 pilot-sweep prediction record, and the archived manifest of the initial release |
| `04_code/lib/` | `certificates.py` (split / PPI++ certificates, finite-population and betting bounds), `neutrality.py` (ρ bounds), `design.py` (menu allocation), `costpredict.py` (pilot-based cost predictors v1–v4), `ledger.py` (unique-label accounting), `figstyle.py` |
| `04_code/6x_*.py` | Pool builders (BEIR stacks; fully judged pools for TREC DL, CAsT 2019, ANTIQUE, NeuCLIRBench) and LLM judges |
| `04_code/63, 67, 70, 72, 77` | Sequential certificates, PPI gain, neutrality diagnostic, self-preference test, mechanism map |
| `04_code/80–83` | Document-level auditing: decision-weight sampling, judge control variates, sampling baselines (incl. `uniform_nz`), active inference, menu allocation |
| `04_code/84–88` | Unified metrics, Table 2 (`86`), exact-certificate table, pilot-size sweep |
| `04_code/93–99` | Figure F4, bootstrap intervals (`94`), variance-dilution cost model (`95`), certificate calculator (`96`), pre-audit rule (`97`), locked predictions (`98`), all figures (`99`) |
| `04_code/RUN_*.sh` | Grids: revised accounting, Track C (`--dump_draws`), NeuCLIRBench lock pipeline |
| `05_results/` | Row-level results per experiment; `unified/` tables and cost-model outputs; `heldout/` locked predictions, scores and the lock note |
| `06_paper/tmlr_submission/` | LaTeX source, figures and compiled PDF; `06_paper/THEORY_v0.1.md` propositions and proofs; `06_paper/make_supplementary.sh` builds the anonymous supplementary zip |

Two kinds of row-level records are attached to releases rather than kept in the tree: the per-draw audit records
(`*_draws.csv`, release `draw-records-v1`; regenerated by `81_sampling_baselines.py --dump_draws`, needed by `94_j50_ci.py` and
`97_pilot_rule.py`) and the pilot-only prediction records that were committed as locks before each audit (`*_predict.csv`, release
`locked-predict-records-v1`; their lock commits remain in the history, and the derived `05_results/heldout/PREDICTIONS_*` files stay
in the tree). Extract both archives into `05_results/`.
During double-blind review the archives are not part of the supplementary zip (size); the outputs of the two scripts that need them
(`05_results/unified/J50_CI_*.csv`, `PILOT_RULE_*.csv`, `05_results/heldout/PILOT_RULE_*.csv`) are committed, and the archives can be
provided on request through the Action Editor. Every other table and figure regenerates from the committed result files alone.

## Reproduction
Requirements: Python 3.11, numpy, pandas, scipy, scikit-learn; for pools and judges also torch, `transformers==4.51.3`,
`sentence-transformers==3.4.1`, bm25s and one 24 GB GPU. Run grids with one BLAS thread per process (`OMP_NUM_THREADS=1`); the
run scripts do this and cap concurrency at the CPU quota.

- Pools: `61_build_pool.py` (BEIR), `64/75/87/89/100` (fully judged pools). Judges: `66_llm_judge.py <name> --cand <dir> --texts ... --queries ...`.
- Tables and figures from the committed results: `python3 04_code/86_table2_v2.py v3`, `python3 04_code/95_cost_model.py`,
  `python3 04_code/96_ppi_calculator.py`, `python3 04_code/93_plot_F4.py`, `python3 04_code/99_figures.py`.
- Fixed-budget grid with per-draw records: `04_code/RUN_TRACK_C.sh`; the NeuCLIRBench locked test: `04_code/RUN_NEUCLIR.sh {pool|judge|predict|audit}`.
- Paper: `cd 06_paper/tmlr_submission && pdflatex main && bibtex main && pdflatex main && pdflatex main`.

The candidate pools (`pools_bundle`: features, human labels and judge outputs per pooled pair, plus the pooled document texts)
are distributed separately because the texts inherit the licences of the source collections; the pool CSVs without texts are
sufficient for every experiment except re-running a judge.

## Pre-registration record
`03_data/PROSPECTIVE_LOCK_v0.4–v0.6` govern the three external evaluations of the paper; `PROSPECTIVE_LOCK_v0.7` governs the
NeuCLIRBench test of the pre-audit rule. `05_results/heldout/LOCK_NOTE.md` lists, in order, every lock commit, every audit, the
one formula bug found in a lock, and which predictors were fixed before or after which audit. Nothing in that note is edited
after the fact except to append.

What the commit history shows: the held-out prediction locks (`54deba0`, `694e00b`) and the NeuCLIRBench lock v0.7 (`1750865` text,
`b833065` / `ad91bfd` predictions) are separate commits that precede the audits they govern. What it does not show: the locks v0.4–v0.6
entered this repository in its first commit together with their results (they were written in the private development repository
before the target data were accessed), and the history was rewritten once for attribution, so commit timestamps are not independent
evidence of timing. Readers who need such evidence should treat the pre-registration as self-reported.

Pilot-rule scores: `05_results/unified/PILOT_RULE_eps*.csv` and `PILOT_RULE_single_eps*.csv` (development collections) and
`05_results/heldout/PILOT_RULE_single_{llm,rr}_{ho,ho10}_eps*.csv` (TREC-COVID / Touché) are the outputs of `97_pilot_rule.py` on the
release draw records; they are committed so that Table 4 and the in-text rule numbers can be checked without the release assets.
